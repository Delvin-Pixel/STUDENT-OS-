# B58.1 — Hardening Candidate

B58.1 is the pre-GitHub hardening candidate produced from the audited B58 entitlement checkpoint.

## Fixed locally

- Vitest discovery includes shared tests and TSX test/spec variants.
- App, test, and config TypeScript checks are separated.
- Service-worker activation integrity source checks assert valid anchors before ordering.
- Transition provenance is fail-closed: learner workspace data cannot self-assert official/verified authority; server workspace persistence downgrades privileged claims and strips learner verification timestamps.
- Ghana transition rule packs remain unverified until backed by real source attestation.
- External Paystack/Hubtel Premium requires provider subscription identity, a valid period end, and fresh verification metadata. Missing, malformed, stale, implausibly future-dated, ended, or inactive authority fails closed.
- Explicit manual active Premium can be non-expiring; manual trial/cancel states require a period end.
- A server-side capability authorization helper exists for B59/B60.
- Secret scanning cannot false-pass with zero enumerated files.
- Drizzle migration metadata validation is machine-checkable.
- The incompatible Builder JSX-location Vite plugin was removed from the project and Vite config.
- The redundant `pnpm` project devDependency was removed; the canonical package-manager version remains `packageManager: pnpm@10.4.1`.
- Node 22.23.3 is pinned for release verification via `.node-version` / `.nvmrc`, with a Node 22 engine boundary.
- Database migration execution was split from migration generation so CI tests committed SQL rather than generating new source.
- Production bundle verification and post-migration subscription schema smoke-test scripts are present.
- CI is hardened with a fixed runner, minimal permissions, pinned action SHAs, strict frozen install, MySQL migration smoke testing, build/bundle checks, dual dependency audits, and deterministic commit-derived archives.
- A semantic ESLint configuration and command are staged.

## Still mandatory before release certification

A networked dependency-backed environment must add/lock the staged ESLint toolchain with pnpm, refresh/prune the lockfile, then run frozen install, source/test/config TypeScript, semantic ESLint, Prettier, full Vitest, production build/bundle verification, real MySQL migrations, dependency audits, and GitHub CI.

B59 remains blocked until those gates are green on the canonical GitHub commit.
