# Welcome screen investigation — 13 Aug (CRITICAL FINDING)

## What happened

The production domain https://studentos-jmnrfmj9.manus.space/ is serving the **Manus dev-previewer build**, NOT the Student OS app bundle:

- HTML at root is correct (Student OS title, welcome meta) — served OK.
- But the only JS chunk listed in the prod HTML references is **index-CqVaqfMP.js** (content-length 1,216,004 bytes — far larger than the local Student OS bundle) and its content starts with `src/modules/DomSelector/EditsToolBar/EditToolbar.tsx` — i.e. the dev previewer's DOM editor module.
- Local dist/public/assets contains only `index-B8t6Y_8H.js` (smaller, app bundle) — the local build does NOT match what prod serves.
- Welcome markers ("Welcome to Student", "Continue with Google/Facebook/Apple/Microsoft/Email") are ABSENT from the served chunk.
- Earlier local dist is STALE (built at 08:57 before Welcome.tsx existed; checkpoint e0c14b18).

## Interpretation

- A fresh build (checkpoint f214408a) was just published; the index.html already references the new chunk name index-CqVaqfMP.js.
- The large chunk size (1.2MB) suggests the build bundled the dev-previewer (perhaps vite build included manus previewer plugin in production, or the dist was generated by a previewer-enabled build path). The previous checkpoint's published build ALSO served previewer code (version.json earlier showed Manus previewer content; the CDP capture of prod root rendered a blank page with only "Made with Manus" badge).
- The user's phone saw onboarding/dashboard (an older real build) then blank/previewer — consistent with a stale PWA cache + now-previewed build.

## Root cause confirmed (resolved)

The local `dist/` was stale (built 08:57 before Welcome.tsx), and checkpoint f214408a's publish used that stale bundle. A fresh `pnpm build` after clearing dist now produces index-T9mDwWjD.js containing all welcome markers (Welcome to Student, Continue with Google/Facebook/Apple/Microsoft/Email). A new checkpoint is needed to republish the correct bundle.
