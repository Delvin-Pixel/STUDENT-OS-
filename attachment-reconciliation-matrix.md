## Newly applied fixes during this attachment pass

The assessment finalization path now uses a database transaction and confirms that the owned session reached `submitted` state before returning success. Reusing a start key for another quiz or a submit key for another session now produces a conflict instead of returning an unrelated result. Material PDF summary and practice-question generation now use the shared text-generation capability predicate, fail clearly when a non-empty model catalog contains no eligible text model, forward the protected request `AbortSignal`, and explicitly define embedded document instructions as untrusted data. AI quiz drafts now support learner editing of difficulty and subtopic metadata, and the canonical `QuizQuestion` type persists those reviewed fields. Focus completion now records the persisted active timer duration rather than a mutable current preference.

## Explicit boundaries

A provider account completing OAuth, platform-side deployment propagation, Android/iOS notification delivery, installed-PWA behavior, screen-lock timing, real PDF/AI provider responses, and second-device synchronization are not safely reproducible as automated sandbox facts. These remain **REQUIRES MANUAL VALIDATION**. The active production domain has rendered its public shell, but the v10 service-worker artifact still requires platform-side propagation confirmation; this is not being represented as a source defect or as a successful deployment-artifact match.
