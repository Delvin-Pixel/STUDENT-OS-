# Student OS Core-System Verification Record

**Scope.** This record validates the account-bound workspace foundation before further feature expansion. It covers authentication boundaries, cloud persistence contracts, account-scoped browser storage, initial hydration, offline handling, conflict behavior, and restoration. It does not treat code inspection or simulated tests as proof of a real OAuth sign-in on a physical second device.

> **Release decision:** every testable core guarantee listed below passed. The remaining items are real-device confirmations that require a learner’s own account and browser or phone; they are intentionally not marked as passed here.

## Repairs made during this validation

The audit found a genuine compatibility risk rather than treating the prior release as sufficient evidence. A cloud workspace saved before currency selection was introduced could be rejected by strict raw validation on a new device. The workspace schema now supplies `GHS` when that legacy field is absent, and the server persists the normalized validated representation on the next save.

The audit also tightened account ownership in Settings data paths. Imports, reset, and onboarding restart now write only to the active account’s local cache. Failed cloud mutations now retain local data and schedule a retry while the browser is online. The hydration decision itself was extracted into a tested policy so restore, pending-local, and failed-cloud outcomes are directly covered.

## Required real-device confirmations

The following checks cannot be honestly completed from automated sandbox validation because they require a real identity provider session, another browser profile or device, and in some cases an installed PWA. They are the final acceptance checks, not known failures.

| Manual check                                                          | Expected observable result                                                                                                           |
| --------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| Sign in on a second phone or laptop with the same account             | The existing profile, tasks, timetable, budget currency, and other cloud-synced workspace data appear after the short loading stage. |
| Sign out from account A and sign in as account B on the same browser  | Account B sees its own workspace or clean onboarding only; no A profile, task, note, lesson, or setting appears.                     |
| Create a task while offline, close/reopen the browser, then reconnect | The task remains locally; the sync indicator shows Offline or Changes pending and later returns to Synced after reconnecting.        |
| Make independent changes on two signed-in devices                     | Both independently created records remain after sync; a same-record edit follows the active-device conflict rule.                    |
| Clear browser site data on a second device, then sign in again        | The account’s cloud workspace restores rather than beginning with an empty dashboard.                                                |

## Conclusion

The testable implementation is now ready for release: its account boundary, storage ownership, cloud hydration, offline preservation, conflict path, and legacy-compatibility path have evidence behind them. This record deliberately does **not** claim that a physical provider login, true cross-device restoration, or installed-PWA offline behavior has already been personally exercised. Those outcomes require the listed learner-side confirmations after the release is live.
