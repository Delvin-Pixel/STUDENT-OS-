## Cloud sync and local-first state

A disposable cloud account restored a representative workspace containing a task, note, exam, timetable event, flashcard deck, goal, and `GHS` setting. A stale simulated second device hit a real revision conflict; its independent note was ID-merged with the first device’s task, then saved at the next revision. The final cloud workspace contained both new IDs with no duplicate IDs.

Browser-native offline mode, physical account switching, and installed-PWA recovery still require a real device or controlled second browser profile.

### Post-audit P0 hardening evidence

The post-audit router and client contracts partition the workspace and private push-history query caches with a stable account scope while deriving authorization only from the server session. A forged workspace cache scope still resolved only the trusted authenticated account in regression coverage. Session discovery no longer serializes the workspace blob. The generic storage proxy now returns `404` for synthetic account-owned study-material and profile-photo paths, while normal account-owned UI access is resolved through protected signed-URL procedures. A direct unauthenticated development request to `workspace.load` returned `401`.

The Settings data actions now distinguish **Refresh this device cache** from **Delete workspace everywhere**. The deletion path is revision-safe, reports a cloud conflict/unavailability instead of a false success, and ignores late pre-delete save results. Desktop and mobile settings captures verified that the two actions are separately visible and reachable. This is controlled UI and contract evidence; a full second-account browser switch and a physical offline/reconnect cycle remain **REQUIRES MANUAL DEVICE TEST**.

## Notifications

The server-side notification regression suite passed for VAPID credential handling, accepted/retryable/expired delivery-status classification, bounded private delivery history, scheduled-dispatch guarding, and payload construction. These checks provide contract evidence for the server path, not proof that a particular browser or phone displayed a notification.

Permission prompts, device registration, visible delivery, disable/re-enable behavior, logout/login behavior, and a second-device result are all **REQUIRES MANUAL DEVICE TEST** checks. No physical push delivery is claimed from this environment.

## Performance work

Route-level lazy loading reduced the initial dashboard JavaScript asset from 1,952,010 bytes to 1,387,923 bytes. Deferring the dashboard’s non-critical Recharts weekly chart reduced it further to 990,485 bytes: a measured **49.2%** reduction from the baseline. The assistant route and budget route were opened successfully after their deferred code was requested. The AI/diagram and syntax-rendering chunks remain intentionally deferred and continue to warrant future optimisation.

## Responsive review

Desktop previews of the dashboard, Today, Materials, and PDF Summary routes loaded successfully. Mobile previews confirmed the dashboard and consent-led material explanations remain readable. The review exposed a mobile layout issue: the floating Quick Add button can overlap the lower material/PDF form controls. A targeted layout correction is tracked before final release.

The post-audit hardening build was also reviewed at desktop (1280×720) and mobile (375×812) on the authenticated dashboard. Both layouts rendered the account workspace, educational lesson loading state, plan cards, quick actions, navigation, and compact mobile hierarchy without a visible overlap or clipped control. This is visual layout evidence only; it does not prove lesson-provider availability or physical-device notification behavior.

## Published endpoint check

The published Student OS URL rendered successfully in the available browser session. A credential-omitted browser fetch to the protected workspace procedure could not complete from that browser context, and the sandbox command-line TLS probe also could not establish a connection. As a stateless alternative, direct extraction of the published `workspace.load` procedure returned `UNAUTHORIZED` with HTTP status 401. The public route and protected procedure boundary are therefore observed live; physical sign-in/switching remains **REQUIRES MANUAL DEVICE TEST**.
