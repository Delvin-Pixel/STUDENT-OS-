# Ultimate Engineering Mission — Learning Workflow Audit

Student OS retains one deterministic learning-intelligence model in `learningIntelligence.ts`. Dashboard recommendations, Today’s execution coach, Reviews, Mastery, and adaptive exam planning derive from this model rather than writing a second priority, scheduler, or mastery store.

| Workflow                     | Evidence                                                                                                                                                                                                | Audit result                                                                                                                                                          |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Priority and execution coach | `getRankedNextActions` ranks due tasks, active/planned sessions, exam-topic work, and due flashcards; `getExecutionCoach` selects only from that result.                                                | No competing priority model found. Active and paused sessions remain first-class; skipped and rescheduled sessions are excluded.                                      |
| Mastery and readiness        | Topic mastery weights direct quiz/practice evidence above session time, uses transparent estimates when evidence is absent, and exam readiness reports coverage separately from evidence-backed topics. | Evidence labels avoid treating a manual topic state as confirmed knowledge.                                                                                           |
| Spaced repetition            | `getDueReviewQueue` is the shared due-card calculation for Reviews and ranked actions.                                                                                                                  | Repaired an inconsistency in which ranked actions used stale `dueDate` even when a later `nextReviewDate` existed.                                                    |
| Adaptive exam plans          | Planning uses bounded capacity and preserves finished work when rebalancing missed plan items.                                                                                                          | Repaired generated same-time blocks: plan creation and rebalance now allocate distinct non-overlapping evening slots.                                                 |
| Manual session lifecycle     | Store actions govern start, pause, resume, completion, skip, and reschedule. Only completion records learning evidence.                                                                                 | Added one shared interval-overlap guard for create, edit, plan-item start, and reschedule.                                                                            |
| Daily command center         | `buildDailyContext` is a read-only projection used by Today. Dashboard uses the same priority engine for recommendations.                                                                               | Repaired in-place sorts that could have silently reordered canonical task, session, or event collections.                                                             |
| AI personalization           | The assistant sends a bounded learner context and applies optional local context in the UI.                                                                                                             | Repaired an in-place exam sort so question personalization no longer mutates workspace ordering. Device-private feedback remains excluded from cloud synchronization. |

Focused regressions cover central ranking, evidence, review queues, plan capacity and timing, lifecycle terminal-state handling, assistant immutable selection, session interval conflicts, and immutable daily context. The quality of individual provider-generated answers and real learner behavior remains an end-user validation boundary rather than an automated learning-outcome claim.
