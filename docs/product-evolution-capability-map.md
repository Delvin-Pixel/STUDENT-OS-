# Student OS product-evolution capability map

## Assessment stance

The uploaded product-evolution specification is treated as a **coherence roadmap**, not a mandate to add parallel systems. The current application already has an authenticated, account-scoped local-first workspace; a deterministic `learningIntelligence` engine; a unified daily context; an adaptive exam-plan generator; spaced repetition; evidence-based mastery; protected material/AI flows; and a single device-push planner. New work must extend those paths.

| Specification area                 | Existing current capability                                                                                                                                 | Verified gap or scope decision                                                                                             | Reuse path                                                                                |
| ---------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| Single student intelligence layer  | `learningIntelligence.ts` provides transparent mastery, ranked next actions, adaptive exam plans, and missed-plan rebalance.                                | Ranking does not yet capture available time, inactivity, confidence/reflection, or a rich explanation bundle.              | Extend `learningIntelligence`, never add a second priority store.                         |
| Daily Execution Coach              | Sessions support planned/in-progress/completed; plan items retain reason and can make linked sessions.                                                      | No explicit pause/resume timestamps, actual duration, skip/reschedule reason, or guided execution panel.                   | Extend `StudySession`, `StudyPlanItem`, StoreContext actions, and `/study` or `/today`.   |
| Priority engine                    | Tasks, nearby exams/topic mastery, and due flashcards feed one ranked list.                                                                                 | Candidate scoring does not fully include plan pressure, recent inactivity, available capacity, or learner reflections.     | Add bounded deterministic signals and human-readable reasons to `getRankedNextActions`.   |
| Exam progress/readiness            | Exams have date, subject, topic statuses, adaptive revision plans, countdown UI, and mastery linkage.                                                       | Readiness is mostly topic status/mastery; syllabus coverage and richer per-topic evidence presentation need integration.   | Extend current exam/topics and `getTopicMastery`; do not create a separate exam database. |
| Mastery                            | Quiz/practice/flashcard/session evidence, recency weighting, and estimates are already separate from manual topic status.                                   | Trend, confidence, and past-question taxonomy are not persisted distinctly.                                                | Extend `LearningEvidence` and current mastery computation only if needed.                 |
| Material review and library        | Account-owned PDF/text uploads, consent-gated summaries, reviewed flashcard saving, topic links, and global search already exist.                           | No rich library processing ledger, generated-quiz relationship, or source-page reference (which must never be fabricated). | Add metadata to `StudyMaterial` only after source provenance is available.                |
| AI reliability and context         | Protected routes, rate limiting, timeouts, labelled fallback, selected-context quiz drafts, and source-owned material summary exist.                        | Provider timeouts remain observed; a reusable compact context builder is not yet shared across every AI surface.           | Derive only selected deterministic summaries on server; never send whole workspace.       |
| Personalized onboarding            | Profile captures level, goals, subjects, study-hours and initial workspace.                                                                                 | Preferred study windows/timezone and optional exam seed flow are absent.                                                   | Extend Profile/onboarding with opt-in, validated fields.                                  |
| Academic calendar and countdown    | Timetable, tasks, exams, sessions, calendar views, and countdown cards exist.                                                                               | Countdown is not yet a full coverage/weak-topics/recommended-sessions briefing.                                            | Derive from current exams, plans, and mastery.                                            |
| Spaced repetition and review queue | Four-grade scheduler stores next review, interval, ease, lapse, and retention; ranked action reports due-card count.                                        | No dedicated cross-subject/exam/topic review-queue filter screen.                                                          | Build queue from existing decks/cards and topic/exam links.                               |
| Streaks and consistency            | Streak, longest streak, completed sessions, goals, habits, and daily/weekly review exist.                                                                   | Planned-versus-actual consistency and subject balance are not yet shown together as coaching.                              | Derive from existing sessions/plans/evidence.                                             |
| Smart reminders                    | One planner handles tasks, exams, study plan, daily goal, streak, saved lessons, custom reminders, quiet hours, caps, local time, device ownership.         | It does not yet use the central priority/exam-readiness signals.                                                           | Extend `planDevicePushReminders`, not a new scheduler.                                    |
| Search and command center          | Global search covers tasks, notes, exams, cards, quizzes, materials, plans, topics; Quick Add supports task/session/card/expense with session confirmation. | Quick Add lacks note/exam/focus/search/AI actions and richer time parsing.                                                 | Extend the existing palette carefully after prioritization work.                          |
| Today and reflection               | Today aggregates existing sources; Reviews provides daily/weekly evidence and next action.                                                                  | Today is read-only and has no optional post-session reflection loop.                                                       | Add reflection as evidence, then consume it in existing intelligence/review functions.    |
| Analytics and weekly review        | Progress has study/XP/charts; Reviews has study minutes, completed sessions/tasks, quiz average, weakest topic.                                             | Actionable subject-balance/exam-pressure insight and mastery trend need a shared insight function.                         | Extend `reviewInsights` plus the existing pages.                                          |
| Adaptive plan and session quality  | Capacity-aware plan generator and rebalance avoid unlimited backlog; sessions have duration/topic/status.                                                   | No actual-vs-planned duration, skip data, or quality/reflection signals.                                                   | Extend session/plan domain with bounded, optional fields.                                 |
| Recovery, backup, account control  | Schema validation, hydration policy, versioned backup envelope, account cache scope, explicit cloud delete, and manual limits exist.                        | Import edge-case matrix and account deletion remain scoped future work; source blob scale migration is documented.         | Preserve existing storage/hydration, use additive migration only.                         |
| Private class spaces               | P3 boundaries are documented.                                                                                                                               | No implementation is appropriate without a server-side membership/moderation/invitation model.                             | Explicitly defer; do not expose a partial social feature.                                 |
| Performance, mobile, accessibility | Route/chart lazy loading, responsive review, shadcn controls, focus semantics, and mobile fixes exist.                                                      | Real Android/slow-network/large-workspace checks remain manual; further chunk work requires measured usage.                | Keep regression and manual-device evidence gate.                                          |

## First implementation boundary

The highest-value coherent increment is a **deterministic execution-coach contract** that enriches the existing priority engine, sessions, plan items, Today, reviews, and reminders. It should capture lightweight execution outcomes and explain recommendations, while preserving the existing cloud/local-first schema migration and avoiding any new scheduler, priority store, or AI context database.
