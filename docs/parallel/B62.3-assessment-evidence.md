## Source-grounded model

Existing assessments use protected tRPC routes and an owner-scoped MySQL
`assessment_sessions` row. Starting a session copies exactly 50 questions
from the account's learner-owned workspace into `assessment_questions`,
storing a SHA-256 snapshot digest. Learners can save one answer per
question. Submitting finalizes the server-computed result into
`assessment_submissions` idempotently, and marks the session submitted.
These controls protect server-side score records **but do not make the
quiz independent, academically reviewed, or official**.

B62.3 introduces a read-only protected query
`assessments.evidenceReview({ sessionId })`. It reads the session only when
`assessment_sessions.openId` matches the authenticated account. It
then loads the matching submission with owner predicate, the immutable
question snapshot, and the saved responses. The server audits:

- Completion and owner alignment for session and submission.
- Exactly 50 consecutively numbered valid question snapshots and valid
  answer options.
- The canonical SHA-256 digest against the original server snapshot hash.
- Exactly one in-range response per question.
- Recomputed correct-count and score matching both the session and
  immutable submission records.
- Consistent server finalization timestamps.

An intact result returns `limited_advisory` with the score and explicit
`source_not_academically_reviewed`,
`academic_context_not_bound`, and `independence_unverified` codes.
Incomplete sessions return `pending_submission`; failed integrity
returns `held_integrity` with a null score. In every case the public
shared response has literal `authoritativeMasteryEligible: false`,
`sourceApproval: "unverified"`, and `independence: "unknown"`.

No question text, answers, account owner IDs, submission idempotency keys,
or reviewer secrets are returned. All inputs to the integrity evaluator
must be loaded by trusted server code; it is not itself a proof of
identity or curriculum approval.

A high score is now described as strong **assessment performance**, never
as proof of verified mastery. These assessment bands are generic feedback,
not official Ghana grading rules.

## Tests and boundaries

Regression tests cover intact, pending and inconsistent submissions,
account ownership mismatches, digest tampering, malformed or incomplete
questions, duplicate/missing/out-of-range answers, score manipulation,
timestamp mismatches, forbidden authority flags, and no mutation or
answer leakage.

B62.3 does **not** introduce authoritative academic evidence decisions,
human reviewer approval, signed curriculum source attestation, or
recorded `academicContextId`/`policyBundleId` bindings to the
current assessment schema. Those need a separately reviewed additive
storage design and owner-bound governance workflow before authoritative
mastery in B62.4. The B62.1 `EvidenceDecisionSchema` intentionally
is **not populated with invented approvals** here.

The live B58.1 database/OAuth/session/protected API gates remain blocked.
A passing GitHub CI run with a temporary MySQL test service cannot
close those runtime release gates. Retain B59–B61 safeguards and keep
this PR in draft, unmerged, with no production rollout.
