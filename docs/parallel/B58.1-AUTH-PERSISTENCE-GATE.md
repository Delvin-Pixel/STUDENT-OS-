## Confirmed source-level defect

Previously `server/db.ts:upsertUser` returned successfully if
`getDb()` was null. The OAuth callback in
`server/_core/oauth.ts` treated that call as successful and could
issue a signed long-lived Student OS session cookie despite the account
having never been durably persisted.

A configured URL also does not itself prove connectivity; verification
must cover the actual write and subsequent read.

## Safe implementation

- An absent database rejects `upsertUser` instead of succeeding silently.
  Existing successful writes retain their behavior.
- OAuth callback verifies the account is readable under the exact OAuth
  provider subject **after** the upsert succeeds and **before** signing
  any session. Missing, wrong-identity, failing, or unreachable reads
  block cookie issuance and return the existing generic OAuth error.
- Existing CSRF/state/PKCE transaction cookies are cleared before
  account persistence, preserving the one-use transaction boundary.
- The existing successful callback test now requires readback; new
  regression tests cover the missing database, failing writes,
  absent or wrong persisted identities, and failed readback.
- Neither raw credentials nor personal OAuth subject identifiers appear
  in operational logs; error responses do not disclose DB URLs.

## Definition of done and verification

The patch is independently **source/CI verified** only after frozen
install, TypeScript app/tests/config, ESLint, Prettier, Vitest, clean
test MySQL migrations, production build/bundle, secret scanning and
dependency audits pass.

**Live functionality remains blocked** until the owner securely
configures a valid Student OS MySQL `DATABASE_URL` on an approved
Preview branch, sets a suitable session secret and OAuth provider
configuration, and exercises both success and failure flows with
actual authenticated accounts. A CI MySQL instance and mocked OAuth
do not constitute successful live login. Never request secrets in
issues, PRs, chat, CI output, or commits.

Recommended live tests after owner setup: independent accounts A/B,
persistent registration/relogin, callback expiration/replay, logout,
missing database, database timeout, wrong-account session,
workspace isolation, and protected API requests. Use privacy-safe
status-code and test-assertion evidence without copying cookies/tokens.
