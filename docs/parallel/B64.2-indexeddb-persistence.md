# B64.2 — Account-scoped IndexedDB cache and non-destructive migration

## Checkpoint and scope

Track B only. Based on CI-verified B64.1 `a67d81297c04a766d8faed05a1bc4e3f9faadb34`. The new `offlineIndexedDbBackend.ts` and `offlineIndexedDbCache.ts` modules are **unwired**; `StoreContext`, `storage.ts`, MySQL, B58.1 authentication, B62 academic state and existing synchronization logic remain unchanged.

The foundation uses the browser's real IndexedDB API, but CI tests use deterministic asynchronous, in-memory protocol mocks. This is **not** a claim of successful Android Chrome/PWA device testing or production adoption.

## Implementation contract

- One versioned database `studentos-offline-cache-v1` with one `account-workspaces` store, keyed by exact authenticated account subject (not a name, profile label or client-supplied identity).
- `createOfflineIndexedDbCache` requires a **caller-supplied current authenticated account accessor**. Every operation checks account scope before and after asynchronous work; reads never return an old-account response after a switch.
- Snapshot envelope stores schema version, server revision, pending flag, save timestamp, JSON payload and SHA-256 digest over all fields including owner and payload. Every read checks shape, semantic workspace consistency, owner, revisions and digest before exposing a sanitized copy.
- Workspace saves require an **expected checksum** and use a single IndexedDB **readwrite transaction** to compare and swap. A missing checksum means _insert only if absent_, preventing migration from overwriting an already populated account cache. The caller must still separately perform the existing authenticated server compare-and-increment check; local CAS is not remote revision authority.
- Sanitize expiring `studyMaterials[].url` and `profile.profilePhotoUrl` before saving/restoring. Keep durable storage references. Input and recovered JSON are capped at 4 MiB, and unsupported/malformed workspaces fail closed.
- `migrateReadOnlyLegacy` reads a caller-provided exact-account legacy snapshot only when IndexedDB has no record. Legacy cache is **never modified, cleared, or overwritten**. Already-present IDB takes precedence; corrupt IDB requires explicit recovery and is **not** silently replaced by old localStorage data.
- Quota failures, unavailable browser storage, interrupted migrations, checksum mismatches and stale async account contexts return bounded statuses. Existing localStorage remains the unchanged source of truth until a separate, reviewed cutover.

## Security and limitations

**Important:** SHA-256 is an accidental-corruption and stale-write detector, **not** authenticity, tamper resistance, encryption, a MAC, trusted account authentication or official academic proof. IndexedDB contents remain readable by JavaScript executing on the same origin; XSS, compromised/shared devices and unlocked sessions remain security threats. Before activation, security review must define whether local device encryption/lock policy and explicit sign-out erasure are needed. The current session-only accessor is supplied by the future authenticated integration, not created by this prototype.

If the account changes _during_ a database transaction, an operation already in progress can still commit under the old account's **distinct scoped key**. The adapter then reports `denied`; it does not promise rollback of an already committed transaction. The future app integration must cancel old-account tasks and resolve writes with a session epoch/lease before starting them. No cross-account read result is returned.

An IndexedDB onupgrade `blocked` event causes a bounded storage error rather than risking an unbounded wait. Old tabs may need to close. No aggressive retry loop, background upload, replication, tombstone compaction, storage eviction or destructive migration exists in this milestone.

## Remaining rollout/acceptance gates

- CI: frozen install, TypeScript app/tests/config, ESLint, Prettier, all tests, clean MySQL CI migration, secret scan, bundle build, audits.
- Browser integration: real IndexedDB transaction/quota/blocked-upgrade tests in Chrome and an installed Android PWA, including offline editing through restart/reconnect, account switching, cache clearing and recovery with malformed snapshots.
- Low-end Android: measure write latency and memory for 256 KiB/1 MiB/4 MiB snapshots, storage pressure, airplane mode, wake/resume and retry behavior over low-bandwidth mobile networks.
- Academic parity: verify JHS, SHS, tertiary, private-candidate and remedial workspace payloads are accepted or rejected solely by common schema, not by assumed institution approval.
- No merge, deployment, live credentials or payment activation without independent review.
