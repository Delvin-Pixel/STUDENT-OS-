## Event contract

The v1 event vocabulary covers source-manifest review, policy-attestation recording, policy publication/suspension/revocation, signer registration/revocation, and signing-key rotation. Each event is scoped to one authority and includes immutable subject identity/version, JHS/SHS/tertiary scope (tertiary requires a programme), actor/reviewer identities and key IDs, detached-signature fields, idempotency request key, occurrence time, previous event hash and event hash.

The hash uses SHA-256 with the domain separator `student-os/academic-governance-ledger/v1\n`. The verifier rejects malformed events, mixed authorities, sequence gaps, reordered/removed entries, altered event contents and previous-hash substitution. The storage migration is intended to preserve event envelopes and provide unique event/request identifiers.

## Security boundaries (important)

- The helper verifies **ledger content integrity and ordering only**. It does not verify Ed25519 signatures, establish key ownership, or establish that a principal represents GES, NaCCA, WAEC, a university, or any other authority.
- Synthetic test signatures are placeholders, not usable credentials.
- A hash chain is tamper-evident only relative to a trusted retained head. It does not by itself prevent a database administrator from rewriting an entire chain or rolling back to an older head.
- Application-level append-only is not enough for production. Before live use, add database permissions that deny UPDATE/DELETE to the writer role, an independently stored/checkpointed head, transactional per-authority sequence allocation/locking, signed checkpoint verification, audited two-person signer onboarding, and key-rotation/revocation validation against a vetted root.
- There is no public API, administrative mutation route, live source loader, production trust snapshot, or automatic mastery/policy activation in this phase.
